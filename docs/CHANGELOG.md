### 🎓 Fork 功能说明

#### Fork ≠ 继续对话

很多人误解：
> ❌ Fork 是让我可以从上次的地方继续对话

实际上：
> ✅ 直接选择"继续原会话"就能从上次的地方继续
> ✅ Fork 是创建一个新的独立会话

#### Fork 的真正作用

```
原会话 (abc123.jsonl)          Fork后 (xyz789.jsonl)
├─ 对话1: 实现功能A            ├─ [复制] 对话1: 实现功能A
├─ 对话2: 添加功能B            ├─ [复制] 对话2: 添加功能B
└─ 对话3: 测试完成             └─ [新方向] 尝试不同实现
   ↓                              ↓
   保持不变                       独立发展
```

#### 使用场景

**应该 Fork 的情况**：
- ✅ 想尝试不同的技术方案（保留原方案）
- ✅ 要做大幅度重构（保留稳定版本）
- ✅ 实验性修改（失败可回退）

**不需要 Fork 的情况**：
- ⭐ 正常继续工作 → 选择"继续原会话"
- ⭐ 修复 bug → 选择"继续原会话"
- ⭐ 增加新功能 → 选择"继续原会话"

> **记住：99% 的情况选择"继续原会话"！**

## v1.1.1 - 2025-11-19

### 🐛 修复严重 Bug：Ctrl+C 退出后的错误

#### 问题描述
用户按 Ctrl+C 退出 Claude 后，终端显示：
```
Error: read EIO
  at TTY.onStreamRead
```
并且终端卡住，无法响应 Ctrl+C，必须关闭终端窗口。

#### 根本原因
1. **stdin 监听器残留** - inquirer 的监听器没有清理
2. **TTY 状态异常** - stdin 处于暂停状态但有残留事件
3. **错误未捕获** - EIO 错误抛出到顶层
4. **进程清理失败** - Node.js 试图清理 TTY 时失败

#### 修复方案

**1. 移除所有 stdin 监听器**
```javascript
process.stdin.removeAllListeners();
```

**2. 添加 stdin 错误处理器**
```javascript
process.stdin.on('error', (err) => {
  if (err.code === 'EIO' || err.code === 'ENOTTY') {
    process.exit(0); // 安静退出，不显示错误
  }
});
```

**3. 全局错误捕获**
```javascript
process.on('uncaughtException', (err) => {
  if (err.code === 'EIO' || err.code === 'ENOTTY' || err.code === 'EPIPE') {
    process.exit(0);
  }
});
```

**4. 捕获 SIGINT 信号**
```javascript
process.on('SIGINT', () => {
  process.exit(0); // Ctrl+C 优雅退出
});
```

**5. 处理 Claude 的 SIGINT 退出**
```javascript
catch (error) {
  if (error.signal === 'SIGINT') {
    // 用户按了 Ctrl+C，正常退出
    process.exit(0);
  }
}
```

#### 修复效果

| 场景 | v1.1 | v1.1.1 |
|------|------|--------|
| Ctrl+C 退出 Claude | ❌ 抛出 EIO 错误 | ✅ 安静退出 |
| 终端卡住 | ❌ 必须关闭终端 | ✅ 立即响应 |
| 错误信息 | ❌ 显示堆栈 | ✅ 干净退出 |

## v1.1 - 2025-11-19

### 🎯 重大改进：完全修复输入卡顿问题

#### 核心改变
使用 `execSync` 替代 `spawn`，让 **cc 完全让出终端控制权给 Claude**

#### 之前的问题
```
cc (inquirer raw mode)
    ↓ spawn
claude 启动
    ↓
两个进程同时监听输入 → 输入卡顿、丢字
```

#### 现在的方案
```
cc (inquirer raw mode)
    ↓ 清理终端状态
    ↓ execSync (阻塞等待)
claude 完全接管终端
    ↓
cc 只是等待，不处理输入 → 输入流畅！
    ↓
claude 退出 → cc 也退出
```

1. **加载动画**

2. **更清晰的提示**
   ```
   ⠸ 正在准备启动 Claude...
   ✔ 准备完成！

   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   ```

### 🔧 技术细节

#### 使用 `execSync` 的优势

```javascript
// 旧方案：spawn（异步，父子进程同时存在）
const child = spawn('claude', args, { stdio: 'inherit' });
// ❌ cc 和 claude 都在运行
// ❌ 都可能监听输入
// ❌ 导致冲突

// 新方案：execSync（同步，父进程阻塞）
execSync('claude -r xxx', { stdio: 'inherit' });
// ✅ cc 阻塞等待，不处理任何输入
// ✅ claude 独占终端
// ✅ 零冲突
```

#### 状态清理流程

1. **关闭 raw mode**
   ```javascript
   process.stdin.setRawMode(false);
   ```

2. **暂停输入流**
   ```javascript
   process.stdin.pause();
   ```

3. **延迟稳定**
   ```javascript
   await new Promise(resolve => setTimeout(resolve, 100));
   ```

4. **启动 Claude**
   ```javascript
   execSync(command, { stdio: 'inherit' });
   ```
